# Сетевая игра на Windows и Linux

Оба игрока должны использовать одну версию проекта. В обычной партии два
игрока: хост создаёт комнату, гость подключается и нажимает «Готов», затем
хост нажимает «Начать партию».

## Локальная сеть, VPN или прямой IP

Steam не требуется. В меню «Сетевая игра» есть блок **LAN / IP**.

1. Хост выбирает порт (по умолчанию **8124**) и нажимает «Создать».
2. Гость вводит локальный IP компьютера хоста и тот же порт, нажимает
   «Присоединиться». `127.0.0.1` подходит только для двух окон на одном ПК.
3. Разрешите игре входящий **UDP** на выбранном порту в файрволе хоста.
   Для разных домашних сетей используйте общий VPN или публичный адрес
   хоста с пробросом UDP-порта на роутере. При CGNAT прямой вход без VPN
   или внешнего сервера может быть недоступен.

Windows и Linux подключаются друг к другу одинаково, через ENet.

## Steam через интернет

Запустите Steam под разными аккаунтами на двух компьютерах. В меню сети
используйте блок **Steam**: создание комнаты, поиск либо приглашение друга.
Steam API должен успешно инициализироваться; одного наличия DLL недостаточно.
Неудачное соединение отменяется через 20 секунд; во время поиска входа
можно нажать «Отмена». Прямое IP-подключение остаётся доступно без Steam.

В проекте используется тестовый App ID 480. Для выпуска нужна собственная
настройка приложения Steamworks. Отправляйте всю папку экспортированной
игры с библиотеками, а не только exe или x86_64.

## Запуск из исходников

Windows (PowerShell):

```powershell
.\start-network.ps1 -Godot "D:\Steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe"
# Открыть редактор:
.\start-network.ps1 -Godot "D:\Steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe" -Editor
```

Скрипт создаёт локальную копию редактора в `.network-tools` с библиотекой
Steam API из проекта. Это устраняет конфликт со старой `steam_api64.dll`
рядом со Steam-версией редактора (ошибка загрузки 127), не меняя установку Steam.
Нужен обычный редактор Godot без .NET, совместимый с проектом (проверен 4.7.2).

Linux:

```sh
sh start-network.sh
# Если Godot не в PATH:
GODOT=/path/to/godot sh start-network.sh
```

## Экспорт

В `export_presets.cfg` есть Windows Desktop и Linux x86_64. Установите
шаблоны экспорта **той же версии**, что и редактор. Экспортируйте через
редактор, запущенный указанным выше способом. Godot включит соответствующие
GodotSteam DLL/SO и зависимости из `.gdextension`. Сохраняйте их расположение.
На Linux выдайте исполняемому файлу право запуска: `chmod +x Tanchiki.x86_64`.

## Проверки

В двух терминалах, из корня репозитория (на Windows замените `godot` на путь
к `.network-tools/godot.exe`):

```sh
godot --headless --path godot res://tests/net_peer.tscn -- host
godot --headless --path godot res://tests/net_peer.tscn -- client
```

Для проверки потерь и задержки замените `net_peer` на `net_stress`.
`net_connection.tscn` проверяет пустой адрес, занятый порт, таймаут и
повторное создание хоста после таймаута.

Описание UDP/NAT в документации Godot:
https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html
