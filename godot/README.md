# Тянчики — Battle Tanks (порт на Godot 4)

Порт браузерной версии (`../index.html` + `../src/*.js`) на **Godot 4 / GDScript**
(проверено на 4.7.2).
Сетевой режим убран — только одиночная игра и «горячий стул»; всё остальное
сохранено один в один: режимы, перки, челленджи, гараж, косметика, достижения,
ежедневные задания, погода, разделённый экран, ru/en.

## Запуск

1. Открыть Godot 4.3 или новее → **Import** → выбрать `godot/project.godot`.
2. Нажать **Play** (F5). Главная сцена — `res://scenes/main.tscn`.

Прогресс сохраняется в `user://profile.json`, язык — в `user://lang.cfg`
(на Windows это `%APPDATA%\Godot\app_userdata\Тянчики — Battle Tanks\`).

## Управление

| Клавиша | Действие |
|---------|----------|
| W A S D / стрелки | Движение (игрок 1) |
| Мышь | Прицеливание |
| ЛКМ / Space | Выстрел |
| E / ПКМ | Мина (нужен перк «Миноукладчик») |
| Shift | Рывок-таран |
| Q | Активная способность перка |
| F | Авиаудар (режим «Оборона») |
| P / Esc | Пауза |
| Tab | Табло |

Второй игрок («горячий стул»): стрелки или Numpad 8/4/6/2 — движение,
`<` `>` или Numpad 7/9 — поворот башни, Numpad 0 — выстрел,
Numpad `.` — мина, Numpad `+` — рывок, Numpad `-` — способность.

## Главное меню

Меню собрано так, чтобы целиком помещаться в окно без прокрутки:

* слева — панель действий: профиль, «Выбрать режим», ИГРАТЬ, подсказки
  по управлению и разделы (гараж, галерея, достижения, задания, статистика,
  звук, язык, выход, сброс прогресса);
* «Выбрать режим» раскрывает вторую панель справа от первой — тип игры,
  режим, сложность, уровень и цвета танков. В веб-версии этот блок раскрывался
  внутри той же колонки и её приходилось прокручивать;
* обе панели считают высоту от содержимого и центрируются по вертикали,
  поэтому при любом размере окна от 1024×640 (это минимум, он выставляется
  в `game.gd`) ничего не обрезается и не прокручивается.

Фон — процедурная сцена `menu_scene.gd`: ночное небо градиентом, луна,
плывущие тучи, разбитый город с редкими горящими окнами, две гряды холмов,
скальный гребень с танком, догорающие остовы с огнём, искрами и дымом,
косой дождь, редкие молнии и виньетка. Ассетов нет — всё рисуется в `_draw()`;
плавные засветки сделаны через `GradientTexture2D`, поэтому на градиентах
нет колец и полос.

## Настройки

Экран «⚙ Настройки» открывается из главного меню и из паузы. Значения лежат
в `user://settings.cfg` **отдельно от профиля**: сброс прогресса не должен
сбрасывать громкость и разрешение. Каждое изменение применяется сразу
и сохраняется; внизу есть возврат к заводским значениям.

| раздел | что настраивается |
|---|---|
| Видео | режим экрана (окно / полный экран / без рамки), разрешение, вертикальная синхронизация |
| Графика | спецэффекты (выкл / средне / высоко), погода, сила погоды, цикл дня и ночи, горящие остовы, тряска экрана |
| Звук | общая громкость, звуковые эффекты, музыка |

Про звук: заведены отдельные шины `Master → SFX` и `Master → Music`
(создаются кодом в `audio.gd`, файла раскладки шин в проекте нет). Ползунки
управляют шинами напрямую. **Музыки в игре пока нет** — весь звук процедурный
и состоит из эффектов, так что ползунок музыки сейчас управляет тишиной;
шина заведена заранее, чтобы добавленному позже треку ничего не пришлось
менять. Это же написано подсказкой прямо в меню.

Про погоду: в игре четыре условия — ясно, дождь, туман, гроза. **Снега нет**,
это была бы новая механика погоды, а не настройка. Выключатель убирает
дождь, туман и вспышки, а ползунок «сила погоды» их приглушает, не убирая
совсем; «цикл дня и ночи» отдельно отключает ночное затемнение и ночную
тонировку — на слабых машинах и просто по вкусу.

Старые кнопки «🔊 Звук» и «✨ Эффекты» из футера меню убраны: обе теперь
живут внутри настроек.

## Навигация ботов

Боты застревали у стен по нескольким независимым причинам — все они найдены
замерами в `tests/smoke.tscn` и исправлены:

1. **Вечный рывок.** `dash_range` гасился пройденным расстоянием, а «мозг»
   во время рывка не рулит вообще. Танк, воткнувшийся в стену на рывке,
   расстояние не набирал и оставался в этом состоянии до самой смерти
   (в замерах — до 3 секунд неподвижности). Теперь рывок отменяется, если
   три тика подряд нет продвижения (`tank.gd`).
2. **Вызволение работало не везде.** Попытка выбраться из затора жила внутри
   `_move_toward`, а боевые манёвры (стрейф, отход) идут мимо него через
   `_steer` — зажатый в бою танк простаивал секундами. Вызволение поднято
   в начало `update()` и работает в любом состоянии: бот выбирает лучевым
   прощупыванием самое свободное направление и едет туда ~30 тиков.
3. **Руление «первое свободное направление».** Перебор из семи углов
   останавливался на первом незанятом, из-за чего танк регулярно вжимался
   в стену под острым углом. Теперь направления оцениваются: отклонение от
   курса, свободная длина коридора впереди и сторона прошлого обхода
   (гасит дребезг влево-вправо). Если свободных нет вовсе — бот сдаёт назад,
   а не стоит столбом.
4. **Недостижимые путевые точки.** Бот упирался в точку маршрута до истечения
   таймера. Теперь отслеживается прогресс к точке: нет сближения 40 тиков —
   точка пропускается, а маршрут перестраивается. Точки, оставшиеся позади,
   отбрасываются сразу после построения пути.
5. **Метание в CTF.** Роль (догнать флаг / сопровождать союзника / вернуть
   свой) переигрывалась каждый тик, а внутри стоят случайные броски —
   цель прыгала по карте, A* пересчитывался почти каждый тик, и бот топтался
   на месте. Роль держится `state_timer` тиков.

Заодно вычищены лишние расчёты: перебор целей шёл двумя одинаковыми проходами
с трассировкой видимости, вызывался каждый тик и для всех врагов сразу.
Остался один проход, раз в 3–6 тиков и только для шести ближайших кандидатов;
A* не запускается, когда цель ближе 56 px, и не долбится каждый тик при
недостижимой цели.

Результат по дымовому тесту (60 секунд игрового времени на режим):

| | было | стало |
|---|---|---|
| время в контакте со стеной | 2.0–3.2 % | 0.2–1.3 % |
| самый долгий простой бота | 46–180 тиков | 3–16 тиков |
| путь ботов в CTF | 2591 px | ~4100 px |
| шаг симуляции, «Царь горы» (41 бот) | ~29 мс | ~12 мс |
| шаг симуляции, CTF | ~13.7 мс | ~1.5 мс |

Счётчики `GameMap.stat_*` и `Pathfinding.stat_*` оставлены намеренно: по ним
дымовой тест печатает профиль шага (проверки стен, лучи видимости, вызовы A*).

## Баланс режимов

Числа подобраны замерами: в `tests/smoke.tscn` танком игрока управляет
автопилот (обычный «мозг» бота) — эталонный игрок средней руки, по которому
видно, тяжёлый режим или нет. Неподвижный болванчик для этого не годится:
он проигрывает всегда.

### «Оборона» — сложнее

На «Средне» режим проходился почти без сопротивления: пять волн по 5–9 врагов,
а база между волнами успевала восстановиться полностью.

| | было | стало |
|---|---|---|
| волн | 5 | 7 |
| размер волн | 6, 7, 8, 8, 9 (≈33 врага) | 6, 7, 8, 9, 10, 11, 12 (≈63) |
| рост силы врагов за волну | +8 % | +12 % |
| боссы | одна волна (5-я) | две волны (4-я и 7-я) |
| регенерация базы в паузе | 0.2 %/тик (полное лечение за 8 с) | 0.06 %/тик |
| запас прочности игрока | ×2 | ×1.6 |
| штраф к точности врагов | −0.20 | −0.12 |
| урон базе от врага рядом | 9 HP/с | 10.8 HP/с, радиус 64 → 72 px |
| перезарядка авиаудара | 90 с | 110 с |
| пауза перед волной | 5 с (и старт через 4 с) | 4 с (старт через 3 с) |
| незачищенная волна | ждёт полной зачистки | через 50 с выходит следующая |

Последний пункт важнее прочих: раньше осторожный игрок мог отстреливать
врагов по одному сколько угодно долго, и волна не начиналась. Теперь волны
подпирают друг друга.

Замер: автопилот держится до 5-й волны из 7 и теряет базу на 153-й секунде,
выпустив 41 врага. Живому игроку с перками и апгрейдами 7 волн по силам,
но уже не «на автомате».

### «Захват флага» — компактная карта

Карта была общей на все режимы — 120×68 тайлов (3840×2176 px). Базы стояли
в противоположных углах, по три флага на команду разбрасывались по всей своей
половине. Команды разъезжались в разные концы и за партию почти не встречались:
в замере за минуту — ни одного убийства и 8 живых танков из 8.

Стало:

* карта **64×40** (2048×1280 px) — втрое меньше по площади;
* базы по центру верхней и нижней кромки, друг напротив друга;
* по **2** флага на команду вместо 3, и стоят они не в глубине половины,
  а в двух узких полосах вплотную к центру — обе команды выезжают навстречу
  друг другу и сталкиваются у флагов;
* посреди карты расчищена площадь с симметричными укрытиями — там и идёт
  основной бой;
* лимит захватов снижен с 5 до 3: каждый захват теперь даётся боем,
  и партия укладывается в 3–4 минуты вместо восьми;
* число озёр считается от площади карты (раньше фиксированные 10–20 патчей
  на уменьшенной карте залили бы её водой).

Одной перепланировки не хватило: замер показал 237 убийств за 5.5 минуты
и всего 2 подбора флага. На тесной карте кто-нибудь всегда оказывался
в радиусе боя (450 px), боты навсегда залипали в перестрелке, и флаг
никого не интересовал. Поэтому атакующие в CTF ввязываются в бой только
вблизи (200 px) — отстреливаются они и по дороге, огонь ведётся в любом
состоянии, но цель у них флаг.

Итог замеров одной партии:

| | было (карта 120×68) | стало |
|---|---|---|
| подборов флага за партию | 0 | 11 |
| возвратов своего флага | 0 | 4 |
| убийств | ~0 за минуту | 74 |
| партия завершается | нет | 3 захвата за 1.8 минуты |

### Свои — синие

В командных режимах союзные боты выезжают синими (палитра `ally`), враги
сохраняют цвет своего типа: по силуэту по-прежнему видно, кто перед тобой —
разведчик, тяжёлый или босс.

Раньше `World._spawn_bot` принимал `color_key`, но молча заменял его цветом
типа — союзники в «Захвате флага» выезжали в красном и были неотличимы от
противника. Теперь цвет типа применяется только к врагам.

## Сетевая игра

Партию можно играть вдвоём-вчетвером по сети: и друг против друга, и вместе
против ботов — режим тот же, что выбран в меню хоста.

### Модель: авторитет хоста

Один игрок крутит настоящий мир целиком, включая ботов; остальные шлют
только ввод и рисуют присланное состояние. Клиент не считает ни физику,
ни попадания, поэтому расхождений между экранами не бывает по построению.

Детерминированный шаг-в-шаг (lockstep) напрашивался — у проекта фиксированные
60 Гц и сеяный ГПСЧ, — но отвергнут: в lockstep каждый кадр ждёт ввода самого
медленного игрока, а одно расхождение в последнем знаке float разводит партии
навсегда и чинится только полным пересбором. Для аркады с сорока танками
авторитет одной стороны проще и надёжнее.

### Что и как передаётся

| канал | что | частота |
|---|---|---|
| надёжный | старт партии, состав танков, изменения карты, лента, итог | по событию |
| ненадёжный | снапшот состояния | 20 Гц |
| ненадёжный | ввод игрока | 60 Гц |

Потерянный снапшот не восстанавливают: через 50 мс придёт следующий, а
переспрашивать устаревшее состояние бессмысленно. Потерянный кадр ввода
тоже: танк продолжит ехать, куда ехал, — это заметно меньше, чем задержка
на повторную доставку.

**Карта по сети не передаётся вовсе.** Генератор детерминирован, поэтому
хватает seed: клиент собирает те же 120×68 тайлов у себя. Тест сверяет
отпечатки карт до боя — они совпадают до бита.

### Снапшот

Формат бинарный ([net_protocol.gd](scripts/net/net_protocol.gd)): словарь
с сорока танками весит около шести килобайт, тот же снапшот в байтах —
восемьсот. Углы и здоровье квантуются: точность в четверть градуса на
экране неразличима, а угол вместо четырёх байт занимает два. Признаки
(жив, ускорение, щит, флаг, невидимость, способность) — одно битовое поле.

Координаты остались float32 намеренно: их можно ужать до int16 с шагом
в полпикселя, но карты у режимов разного размера, и любая ошибка в
масштабе даёт телепорты — экономия трёхсот байт того не стоит.

### Сглаживание

Клиент рисует прошлое: положение берётся между двумя пришедшими снапшотами
с задержкой в 120 мс (две длины интервала). Без этого на каждой потере
пакета танки замирали бы.

Пули не интерполируются, а **доводятся** по своей скорости от последнего
снапшота: они летят по прямой, и продолжить их точнее, чем тянуть между
двумя пакетами. Номера пулям не присваиваются вовсе — связывать их между
пакетами ради экономии значило бы усложнить протокол без выигрыша.

### Разрушения и самопроверка

Изменения тайлов пишутся в журнал внутри `GameMap.set_tile`, а не у мест
вызова. Так было не сразу: сначала журнал вёлся при разрушении построек,
и карта клиента расходилась с хостовой — мимо шли деревья под гусеницами
и потоп в «Царе горы».

Поверх этого работает сверка: раз в пять секунд хост шлёт отпечаток карты,
клиент сравнивает со своим и при расхождении запрашивает карту целиком
(16 КБ: тайл и урон по байту на клетку). Надёжный пакет может не дойти при
переподключении, и без сверки у клиента осталась бы стена там, где её
давно снесли.

### Внешний вид и перки

Расцветка, камуфляж и силуэт приходят один раз в составе танка, а не
в каждом снапшоте: они не меняются, и место в пакете им ни к чему.

Перк игрок выбирает у себя, но танк живёт у хоста, поэтому выбор
отправляется туда и применяется там. Уровень сетевому игроку начисляет
мир хоста — тот зовёт его экран выбора отдельным сообщением.

### Проверка

Один процесс не годится: высокоуровневая сеть Godot живёт на дереве сцены,
и двух независимых пиров в одном дереве не сделать. Поэтому тест — два
процесса:

```bash
godot --headless --path godot res://tests/net_peer.tscn -- host
godot --headless --path godot res://tests/net_peer.tscn -- client
```

Проверяется: подключение, объявление партии, совпадение карт по seed,
приход состава, движение по снапшотам, привязка своего танка к камере
и совпадение карт после боя.

Последняя проверка потребовала аккуратности. Первые три попытки показывали
расхождение, которого не было: хост и клиент снимали отпечаток в разные
моменты симуляции, и тест ловил не рассинхрон, а задержку пакета. Честная
проверка выглядит так: хост доигрывает, **замирает**, и только потом обе
стороны сверяют отпечатки неподвижной карты.

### Ограничения

* Подключаться можно только до начала партии: игрок, вошедший в середине,
  состава не получит.
* Предсказания своего движения у клиента нет — танк отвечает на ввод
  с задержкой сети. Для локальной сети это незаметно, для интернета
  потребовалось бы клиентское предсказание с откатом.
* Порт 8124, без обнаружения серверов: адрес хоста вводится руками,
  через интернет нужен проброс порта.

## Силуэты танков и камуфляж

Раньше все танки рисовались одним прямоугольником 24×28, и разведчик
отличался от босса только цветом. Цвет читается плохо: на тёмной карте,
сквозь дым, погоду и постобработку. Силуэт читается всегда — поэтому
у каждой роли теперь свой корпус ([tank_art.gd](scripts/tank_art.gd)).

| роль | корпус | приметы |
|---|---|---|
| Рядовой | 24×28 | обычный ствол |
| Разведчик | 21×25 | узкий клиновидный лоб, три катка, антенна |
| Громила | 29×30 | почти плоский лоб, накладная броня с заклёпками, толстый ствол с дульным тормозом |
| Снайпер | 23×29 | ствол вдвое длиннее любого другого, прицел на башне |
| Миномёт | 25×27 | короткая толстая труба с раструбом |
| Бронемонстр | 34×36 | крупнее всех, спаренные стволы, жёлтые полосы |

### Три разных габарита

Размер влияет не только на вид:

* **корпус** — то, что нарисовано;
* **радиус попадания пули** считается из корпуса: `(w + h) / 4 + 1`. Для
  стандартного даёт ровно прежние 14 px, поэтому обычный бой не поехал.
  Босс ловит пули радиусом 18.5 px — крупная цель и должна быть крупной;
* **габарит для рельефа** ограничен 26×30. Переулок в городе бывает шириной
  в один тайл (32 px): корпус босса в 34 px туда не пролезет, а A* всё равно
  построит через него маршрут и упрёт босса в угол. Замер это и показал —
  самый долгий простой вырос с 27 до 44 тиков, после ограничения вернулся
  к 30.

Ствол считается от края башни и обязан выходить за габарит корпуса:
ствол, кончающийся внутри силуэта, читается как обрубок. Снаряд при этом
рождается не с самого среза, а не дальше `h/2 + 6` — иначе выстрел вплотную
к стене порождал бы снаряды уже внутри неё.

### Камуфляж

Новый тип косметики (`camo`) — базовая окраска корпуса под наклейками:
цифра, осколочный, тигр, пустыня, город, зима. Пятна рисуются в системе
координат корпуса, а не карты: иначе камуфляж «плыл» бы по броне при
движении. Цвета смешиваются с командным (16%), а не заменяют его — в
командных режимах свои должны оставаться узнаваемыми.

Прежний тип `hull` остался и переименован в «Рисунок»: это наклейки
(звезда, пламя, крест), которые ложатся поверх камуфляжа.

### Цена отрисовки

Детализация не бесплатна: на разделённом экране это полсотни танков за
кадр. Катки, ведущие колёса и заклёпки рисуются прямоугольниками, а не
кругами (`draw_circle` — полигон), люк и блик на башне — только у башен
радиусом от 7.5 px. Замер кадра в самой тяжёлой сцене: 29.1 мс до задачи,
38.2 мс с наивной отрисовкой, 32.0 мс после этих правок.

## Скорострельность и перегрев ствола

Замер до правки: игрок делал **3.17 выстрела в секунду** против 1.30
у среднего бота — быстрее в два с половиной раза, а с перком
«Скорострельность» вчетверо. Бой сводился к тому, кто первым зажмёт кнопку.

Лечится двумя вещами сразу:

* базовая перезарядка выросла с 19 тиков до 27 (2.22 выстрела/с в очереди);
* появился **перегрев ствола**: каждый выстрел добавляет жар, жар стекает
  сам, на единице ствол срывается в перегрев и не стреляет, пока не остынет
  до 0.30.

Порог возврата ниже порога срыва намеренно: без этого зазора танк на пределе
стрелял бы рывками по одному выстрелу.

### Числа подобраны замером, а не на глаз

Первая пара констант (0.16 нагрева, 0.0075 остывания) **не работала вовсе**:
при 27 тиках между выстрелами остывание за интервал (0.20) обгоняло нагрев
(0.16), и перегрев не наступал никогда. Счётчик в дымовом тесте показал ноль
срывов за партию — без него ошибку было бы не заметить, потому что игра
при этом выглядела нормально.

Итог по замеру непрерывной стрельбы (`tests/fire_rate.tscn`):

| | выстрелов/с | перегревов за минуту |
|---|---|---|
| было: 19 тиков, без перегрева | 3.17 | — |
| первая пара констант | 2.23 | **0** |
| **стало: 0.20 / 0.0040** | **1.38** | 13 |
| бот на средней сложности | 1.30 | — |

Перк «Скорострельность» теперь даёт 1.28/с устойчиво: он покупает **очередь**,
а не бесконечный поток. Это и было целью — перк остаётся ценным для вскрытия
цели, но больше не ломает потолок.

### Урон пришлось поднять

Резать один темп оказалось нельзя. Замер после правки: «Оборона» стала падать
на 4–6 волне вместо 6–7, потому что вклад игрока в удержание базы велик, и
снижение темпа в 2.3 раза выбило из-под режима опору.

Поэтому урон игрока за выстрел поднят в полтора раза. Выстрелов меньше, но
каждый весомее:

| | урон в секунду |
|---|---|
| было | 79 |
| только снижение темпа | 34 |
| **стало (темп + урон ×1.5)** | **52** |
| бот на средней сложности | 33 |

После компенсации «Оборона» вернулась в свой разброс: три прогона подряд дали
6-ю, 5-ю и 7-ю волну (последний — с 58 HP базы). Ровно так режим и вёл себя
до правки.

Замерять это автопилотом нельзя: он стреляет по цели, а не зажимает гашетку,
и перегрев у него срабатывает раз в три партии. Поэтому есть отдельный тест,
где танк жмёт на спуск каждый тик:

```bash
godot --headless --path godot res://tests/fire_rate.tscn
```

### Что видно игроку

Ствол раскаляется с 25% жара и на перегреве мигает — по нему видно запас,
не отводя глаз в угол экрана. Под полоской здоровья появляется узкая полоса
нагрева (прячется, пока ствол холодный), а из перегретого ствола идёт пар
с шипением.

## Перки и активные способности

Перки были только пассивными: выбрал — и дальше он работает сам. Теперь у
части перков есть поле `active`, и такой перк кладёт в танк **активную
способность** ([abilities.gd](scripts/abilities.gd)) — единственную
механику, где решает момент нажатия, а не набор.

| способность | клавиша | кулдаун | что делает |
|---|---|---|---|
| 🚀 Нитро | Q / Num − | 7 с | 2.5 с ускорения ×1.5 |
| 🔥 Форсаж | Q / Num − | 10 с | 4 с перезарядка вдвое быстрее |
| 🛡 Бастион | Q / Num − | 12 с | 3 с входящий урон ×0.4 |
| 💠 Ударная волна | Q / Num − | 9 с | взрыв радиусом 118 px: сносит постройки, бьёт и отбрасывает врагов |

Способность одна на танк: берётся первая активная из набора перков.
Двух сразу не бывает намеренно — иначе понадобилась бы вторая клавиша,
и выбор перка перестал бы быть выбором.

Кулдаун переживает смерть: иначе размен «умер — получил заряженную волну»
стал бы выгодной тактикой.

Устройство модульное: чтобы добавить способность, достаточно описать её в
`abilities.gd` и завести перк с полем `active`. Ветка в `use_ability`
нужна только для эффекта; кулдаун, длительность, HUD, подсказка клавиши и
поведение ботов работают сами.

**Боты тоже их получают** — в списке перков ботов есть «Нитро» и «Ударная
волна». Правило у каждой своё: волна жмётся только в упор, где гарантированно
задевает, нитро — когда цель дальше 260 px. Бот не копит способность на потом:
у него нет плана на партию, и невыжатый кулдаун — просто потерянная способность.

Пассивный перк «🏗 Осадные снаряды» умножает на 2.2 урон **своих** попаданий
по постройкам. Множитель применяется в `World.hit_building`, то есть одинаково
работает для пули, мины и ударной волны.

В HUD способность показана иконкой, подсказкой клавиши и полосой кулдауна —
это единственное в HUD, что меняется непрерывно, поэтому обновляется каждый
кадр. В окне выбора перка активные карточки помечены золотой плашкой
«АКТИВНАЯ · [Q]»: пассивный перк работает сам, а этот бесполезен, если не
знать клавишу.

## Вторая волна перков

К одиннадцати исходным перкам добавлено двадцать: тринадцать пассивных
и семь активных. Все они привязаны к механикам, которые в игре уже есть —
число без механики это не перк, а строка в таблице.

### Ствол и нагрев

| перк | что делает |
|---|---|
| ❄ Радиатор | остывание ×1.6 |
| 🌡 Термостойкость | нагрев за выстрел ×0.75 |
| 💨 Быстрый сброс | порог возобновления огня выше на 0.25 |
| 🏋 Тяжёлый снаряд | урон +25%, снаряд медленнее |
| 🪶 Лёгкий снаряд | снаряд быстрее на треть, нагрев ×0.8 |
| 🧊 Продувка ствола *(активная)* | мгновенно сбрасывает весь жар |
| ⚙ Разгон *(активная)* | 4 с перезарядка вдвое быстрее, но и жар вдвое |

«Разгон» — единственная способность с платой: скорострельность покупается
жаром. Без этого она была бы просто лучше «Форсажа».

### Покрытие под гусеницами

| перк | что делает |
|---|---|
| 🛣 Асфальтоукладчик | по асфальту и мостам ход ×1.18 |
| 🌾 Вездеход | трава и песок больше не тормозят |
| 🕸 Шипы *(активная)* | 5 с любое покрытие держит как асфальт |

«Вездеход» отыгрывает штраф мягкого грунта, но не даёт прибавки на
асфальте: это перк проходимости, а не скорости.

### Материалы построек

| перк | что делает |
|---|---|
| 🪓 Лесоруб | урон по дереву ×2.5 |
| 🧱 Бетонолом | урон по бетону ×2.2 |
| 🔩 Консервный нож | урон по железу ×2.5 |
| 🧰 Мародёр | снесённая рядом постройка чинит на 3 HP |

«Консервный нож» не украшение: у железа сопротивление пулям 0.5, и без

### Слышимость

Здесь понадобилась новая механика: **боты слышат выстрелы**. Выстрел
в радиусе 520 px зовёт ботов без цели проверить источник. Без этого
«Глушитель» не имел бы смысла.

| перк | что делает |
|---|---|
| 👂 Острый слух | дальность слышимости ×1.7 |
| 🤫 Глушение | ваши выстрелы боты слышат вдвое ближе |
| 🔇 Глушитель *(активная)* | 6 с выстрелы не слышны вовсе |
| 🌫 Дымовая завеса *(активная)* | 5 с боты не видят вас дальше 150 px |
| 🔧 Полевой ремонт *(активная)* | чинит треть запаса |

### Видимое состояние

У каждой длящейся способности свой знак на танке: клубы дыма у «Завесы»,
глушитель на срезе ствола, раскалённое кольцо у «Кумулятива», искры
из-под гусениц у «Шипов», пульсирующее кольцо у «Разгона». Полоски
кулдауна в углу мало — по ней не видно, работает ли перк прямо сейчас.

### Две ошибки, которые поймал замер

**Бот на звук шёл рулением, а не маршрутом.** `_steer` обходит препятствие
только локально, и бот, у которого источник звука за домом, упирался
в стену намертво: замер поймал упор в 8910 тиков — почти две с половиной
минуты. Лечится маршрутом через A*.

**Таймер звука обновлялся бесконечно.** У базы в «Обороне» стреляют
непрерывно, и бот навсегда оставался в режиме «иду проверять». Теперь
новый звук не перебивает тот, на который бот уже идёт.

Оба раза числа было видно только в дымовом тесте: на глаз бой выглядел
нормально.

### Проверка

Перк легко описать и забыть подключить. Отдельный тест надевает каждый
новый перк на танк и сверяет то число, на которое тот обязан влиять:

```bash
godot --headless --path godot res://tests/perks_check.tscn
```

Одиннадцать проверок: нагрев, ход по газону (с перком и по нажатию),
урон по трём материалам, слышимость в обе стороны и то, что «Глушитель»
действительно отменяет оповещение ботов.

Достижения ([achievements.gd](scripts/achievements.gd)) — вехи прогресса

Новые опираются на системы, которых в веб-версии не было:

| 🏗️ Подрывник | снести 60 бетонных и железных построек | материалы: бетон и железо держат втрое больше дерева |
| 🧨 Мастер сноса | то же, 250 построек | |

Под них добавлены четыре статистики профиля: `bridgeKills`,

## Город: покрытия, река и мосты

Карта больше не «поле со случайными стенами»: генератор
([level_gen.gd](scripts/level_gen.gd)) строит город слоями, и порядок слоёв
важен.

1. **Сетка улиц.** Вертикальные и горизонтальные проезды шириной 2–3 тайла
   с шагом 9–17 тайлов. Это скелет карты: по асфальту едут и игроки, и боты.
2. **Кварталы** между улицами: 72% застройка, 18% парк, 10% площадь или
   парковка.
3. **Река** поперёк города — стирает всё, через что течёт, поэтому набережная
   получается там, где вода съела часть квартала.
4. **Мосты** на улицах, пересекающих реку. Первая и последняя улица получают
   мост обязательно, остальные — через одну: переправы должны оставаться
   узкими местами, за которые стоит драться.

Река есть только в «Каждый за себя» и «Царе горы»: «Оборона» и «Захват
флага» собраны под свою геометрию, и река поперёк ломала бы выверенный
баланс.

Внутри квартала дома делятся переулками на 1–3 участка, у крупных бывает
внутренний двор со сквозной подворотнёй, а у 45% — бетонные колонны, которые
не сбить ничем. Из-за них даже полностью разрушенный дом оставляет укрытие.
В парке — газон, дорожки крест-накрест, деревья и иногда пруд с песчаным
берегом.

### Покрытия

Под гусеницами теперь не один «пол», а четыре покрытия
([surfaces.gd](scripts/surfaces.gd)):

| покрытие | тайлы | ход | пыль | звук |
|---|---|---|---|---|
| асфальт | улица, мост | ×1.12 | тёмно-серая | сухой щелчок |
| земля | тротуар, двор | ×1.0 | бурая | шорох |
| газон | парк | ×0.92 | зелёная | шорох |
| песок | берег | ×0.85 | жёлтая | шорох |

Множитель применяется к ускорению, а не к скорости напрямую — но это одно и
то же: предельная скорость равна `accel / (1 - FRICTION)`, поэтому по
асфальту танк и разгоняется быстрее, и едет быстрее, а в песке буксует.

Звук хода играет **только у танков живых игроков**: сорок ботов на карте
превратили бы его в кашу.

### Разметка

Асфальт рисуется без единого лишнего тайла: бордюр появляется там, где
проезжая часть кончается, а осевая — только если полоса шириной не больше
трёх тайлов (`не замощено(c-2) и не замощено(c+2)`). Из-за этого площади и
парковки остаются чистым асфальтом, а перекрёстки — пустыми: тайл, у которого
замощены все четыре соседа, разметки не получает вовсе.

Мост считается тем же покрытием, что и улица, поэтому линии не обрываются
перед въездом, а перила ставятся только по внешним краям настила.

Страховка связности (`GameMap.ensure_connectivity`) при прорубании коридора
через воду кладёт **мост**, а не сухую канаву посреди реки.

## Прочность построек и разрушения

Раньше любая разрушаемая постройка ломалась с одного попадания. Теперь у
каждой есть материал, и он определяет прочность, сопротивление разным типам
урона и то, как здание разваливается ([materials.gd](scripts/materials.gd)).

Материал **не хранится в карте**: он выводится из тех же координат, что и
вариант крыши в отрисовке. Поэтому вид постройки честно сообщает игроку её
прочность — профнастил и выглядит железным, и держит как железный.

| материал | прочность | пули | взрыв | попаданий пулей | как разваливается |
|---|---|---|---|---|---|
| дерево | 30 | ×1.15 | ×1.6 | 1–2 | длинные щепки, доски лопаются одна за другой |
| кирпич | 75 | ×1.0 | ×1.2 | 3 | крошево, красноватая пыль |
| бетон | 160 | ×1.0 | ×0.8 | 6–7 | тяжёлые плиты, густое облако пыли, сильная тряска |
| металл | 110 | ×0.5 | ×1.35 | ~8 | рваные листы, искры, звонкий удар |

Асимметрия сопротивлений — главное в этой таблице: **железо почти не берут
пули, зато его рвёт взрывчатка**, а бетон наоборот лучше держит взрыв, чем
расстрел. Против профнастила выгоднее мина или перк «Взрывные пули», а не
упорная стрельба в упор.

Урон копится в отдельном массиве `GameMap.damage` (байт на тайл) — формат
тайлов не тронут: тип тайла говорит «что стоит», damage — «насколько разбито».
Урон намеренно **не увеличивает `map.version`**: перерисовывать кэш миникарты
и карту затенения нужно только когда постройка действительно исчезла.

### Стадии и характер разрушения

Повреждения видны до разрушения и растут по мере обстрела, рисунок
детерминирован координатами тайла (трещины не «дрожат» между кадрами):

* **дерево** — трескается вдоль досок и теряет их целиком;
* **металл** — мнётся вмятинами, у края отгибается лист;
* **камень и бетон** — сетка трещин из точки удара, затем сквозные дыры.

При разрушении вылетают обломки (`Ent.Debris`): форма, скорость, вращение,
время жизни и цвет берутся из материала. Щепка длинная и вертлявая, бетонная
плита тяжёлая и почти не крутится, лист железа летит далеко и быстро
вращается. Обломки тормозят о землю, ложатся и через 1.5–3 секунды тают.
Одновременно на карте их не больше 300.

Звук тоже свой: сухой треск дерева, низкий гул камня, звонкий удар по железу —
всё синтезируется в `audio.gd`, файлов не добавилось.

### Что это меняет в игре

Мины и взрывные пули теперь вскрывают постройки по площади (раньше мина
ломала только танки) — заминировать проход стало осмысленно. Укрытия живут
дольше, поэтому перестрелки идут вокруг них, а не через мгновенно снесённую
стену. Достижения на разрушенные постройки («Разрушитель», челлендж перка
«Толстая броня») стали чуть медленнее, но дерево по-прежнему ломается
с одного-двух выстрелов.

Неразрушаемый бетонный **периметр карты** (`T_WALL`) остался неразрушаемым:
это каркас уровня, и дыры в нём ломали бы связность.

## Погода

Система погоды была: цикл дня и ночи на десять минут, четыре условия
(ясно, дождь, туман, гроза) и молнии. Проблема была не в наборе, а в том,
что **до ночи почти невозможно было дожить**: партия длится две-четыре
минуты, а цикл стартует в дневной фазе. И ни одно условие не влияло
на правила — погода была картинкой поверх боя.

### Что добавлено

* **Снег** — пятое условие: хлопья с боковым сносом, выбеленная земля
  и, главное, скользкий грунт.
* **Выбор погоды и времени суток** прямо в меню боя: «Своя / ☀ / 🌧 / 🌫 /
  ❄ / ⛈» и «Цикл / День / Закат / Ночь / Полночь». Выбранное закрепляется:
  условие не меняется, а цикл дня стоит — иначе выбранная ночь через две
  минуты превращалась бы в рассвет.
* **Густой туман** плотнее прежнего: пятен четырнадцать вместо девяти
  и они непрозрачнее.

### Связь с правилами

Каждое условие несёт два числа:

| условие | зрение ботов | сцепление |
|---|---|---|
| ясно | 473 px | 1.00 |
| дождь | 402 px | 0.94 |
| гроза | 284 px | 0.92 |
| снег | 355 px | **0.80** |
| **густой туман** | **199 px** | 1.00 |

Время суток умножается сверху: днём света 0.88, в полночь 0.14, и зрение
ботов падает с 473 до 307 px. В туманную ночь бот и правда почти слеп —
но и игрок тоже, поэтому это честно.

Сцепление уходит в тот же множитель хода, что и покрытие под гусеницами:
по снегу танк разгоняется и держит дорогу заметно хуже. Активные «Шипы»
это отменяют — на то они и шипы.

### Две ошибки, которые вскрыл замер

**«Полночь» была светлее «ночи».** Фаза 0.88 уже ползёт к рассвету:
самая тёмная точка цикла — ровно 0.75. Свет получался 0.27 против 0.18.

**Метки времени не совпадали с кривой света.** Самая тёмная точка
называлась «вечер», а «ночью» звался подъём к рассвету — снимок
с выбранной ночью подписывался «закат». Границы сведены с кривой,
добавлена «полночь».

Ещё одна ошибка вскрылась на снимке, а не в числах: **снежный покров
полноэкранным слоем уводил всю сцену в бурый** — цветокоррекция
подхватывала осветление и грела его. Подкрашивать надо саму землю,
а не кадр: цвета земли, газона и асфальта считаются один раз на кадр,
лишних вызовов рисования не появляется.

### Проверка

```bash
godot --headless --path godot res://tests/weather_check.tscn
```

Каждое условие ставится принудительно, и сверяются те два числа, ради
которых погода существует в правилах: дальность зрения ботов и сцепление.
Плюс проверка, что выбранное время не уплывает и что снег доходит
до хода танка.

## Постобработка и эффекты

Всё это вешается **на `SubViewportContainer`**, а не на весь экран: контейнер
показывает уже готовую картинку мира, поэтому эффекты накрывают только игру,
а HUD, меню и оверлеи остаются чистыми и читаемыми.

```
SubViewportContainer  ← material = post_fx.gdshader (градация, bloom, виньетка)
└── SubViewport
    ├── ColorRect             фон
    ├── WorldView             мир + карта затенения (AO)
    └── GlowLayer             ореолы источников, аддитивное смешивание
```

### Цветокоррекция — `shaders/post_fx.gdshader` + `scripts/fx/post_fx.gd`

Порядок как в киношном пайплайне: свечение → экспозиция → подъём чёрного →
контраст → насыщенность → раздельная тонировка теней и светов → виньетка.

Ключевая мысль: градация не статичный «фильтр», а продолжение погоды.
Параметры ведёт уже существующий цикл дня и ночи (`WeatherSystem`):

| условие | что делает |
|---|---|
| ночь (`light` → 0.18) | насыщенность 0.80, тени уходят в синий, виньетка 0.34 |
| день (`light` → 1.0) | насыщенность 1.06, тёплые света, виньетка 0.16 |
| туман | подъём чёрного +0.07, насыщенность −28 %, контраст −14 % |
| дождь | насыщенность −18 %, тени холоднее |
| молния | экспозиция +0.38 на вспышку |
| HP игрока < 35 % | обесцвечивание до −45 %, тени в красный, виньетка +0.25 |

Крутить в `post_fx.gd`: словари `DAY` и `NIGHT`.

### Свечение — два разных механизма

1. **Экранный bloom** (в том же шейдере): яркие пиксели выделяются порогом
   и размываются двумя кольцами по 6 выборок. Полноценный многопроходный
   блюр здесь не нужен — светящиеся объекты мелкие и контрастные.
   Крутить: `bloom`, `bloom_threshold`, `bloom_radius`.
2. **Ореолы источников** (`scripts/fx/glow_layer.gd`): отдельный `Node2D`
   с `BLEND_MODE_ADD` рисует радиальные градиенты там, где по смыслу есть
   свет — трассеры, ракеты авиаудара, оружие на карте, выпавшие перки, ядро
   базы, искры взрывов. Это дёшево (десятки квадов) и даёт основную часть
   эффекта даже с выключенным экранным bloom.

Отдельный узел нужен потому, что режим смешивания задаётся материалом всего
`CanvasItem` — внутри одного `_draw()` его не переключить.

### Затенение у стен — `scripts/fx/ao_layer.gd`

**Настоящий SSAO в 2D невозможен**: он читает буферы глубины и нормалей,
которых у двумерной сцены нет. Но исходные данные здесь даже лучше, чем в 3D —
известна вся карта, поэтому перекрытие считается прямо по тайлам:

1. маска препятствий: стена и кирпич = 1;
2. взвешенное усреднение 3×3 — в вогнутом углу соседей-стен больше, значит
   и затенение сильнее (ровно то, что делает AO);
3. из результата вычитается сама стена: тень нужна на полу рядом, а не на
   верхушке стены;
4. текстура «пиксель на тайл» растягивается на карту, мягкость даёт
   билинейная фильтрация видеокарты — блюр не нужен.

Пересчёт только при изменении карты (пули ломают кирпич) и не чаще раза
в 30 кадров; картинка собирается сразу в `PackedByteArray`, потому что
8000 вызовов `set_pixel` давали заметный рывок.
Крутить: `STRENGTH` (глубина тени) и `SELF_SHADING`.

### Горящие остовы

На месте подбитого танка остаётся обгоревший корпус (`Ent.Wreck`): лежит под
тем же углом, что стоял танк, рядом валяется сорванная взрывом башня, сверху
пляшут язычки пламени, вверх идут искры и дым. Живёт 3 секунды
(`Cfg.WRECK_LIFE = 180` тиков) и последние 45 тиков плавно гаснет
(`Cfg.WRECK_FADE`). Чистая декорация: ни столкновений, ни урона, в расчётах
боя не участвует, `world.dispose()` их чистит вместе со всем остальным.

Огонь и дым используют общую систему частиц — у `spawn()` появился
необязательный сдвиг скорости, чтобы они поднимались вверх, а не разлетались
во все стороны. Тёплый ореол вокруг остова добавляет `GlowLayer`.

### Цена и переключатель

Замер на Intel UHD 610, 1280×720, одна и та же сцена:

| | кадр |
|---|---|
| эффекты выключены | 16.6 мс |
| градация + bloom + AO + ореолы | 18.4 мс |

То есть весь набор стоит **около 1.8 мс** — узкое место в игре не шейдер,
а тысячи `draw_rect` при отрисовке тайлов. Тем не менее в меню есть кнопка
**«✨ Эффекты»** с тремя положениями (выкл / средне / высоко); уровень
хранится в профиле и применяется при старте партии. «Средне» — градация
и виньетка без экранного bloom.

## Звук

Ассетов в проекте нет ни одного: и эффекты, и музыка синтезируются при
запуске ([synth.gd](scripts/synth.gd) — общий инструментарий,
[audio.gd](scripts/audio.gd) — эффекты, [music.gd](scripts/music.gd) —
саундтрек).

### Выстрел танковой пушки

Один осциллятор звучит как писк из телефона, поэтому выстрел собран из
пяти слоёв, слышимых как один звук:

| слой | что делает |
|---|---|
| дульный щелчок | шум 11 кГц → 3 кГц за 50 мс; без него выстрел «пуфкает» |
| тело | свип шума 3.2 кГц → 240 Гц |
| низкий гул | синус 140 → 33 Гц — именно он читается ухом как калибр |
| лязг затвора | негармонические обертоны через 30 мс после выстрела |
| раскат | тихий низкий шум, докатывается после самого выстрела |

Спецоружие использует те же слои, но ниже и длиннее (`shoot_heavy`).
У каждого звука 2–3 варианта плюс разброс высоты тона при
воспроизведении: сорок ботов, стреляющих одним буфером, слышны как
пулемёт, а не как бой.

### Дальность

У каждого из 16 голосов своя шина с панорамой и фильтром низких частот —
поэтому расстояние передаётся не только громкостью:

* **громкость** — обратная степенная кривая `1 / (1 + (d/300)^1.7)`:
  у самого ствола выстрел бьёт в полную силу и быстро проваливается
  на первых экранах;
* **глухость** — срез фильтра едет с 20 кГц до 1.1 кГц. Высокие частоты
  в воздухе теряются первыми, и ухо читает это как дистанцию куда
  лучше, чем одна громкость;
* **панорама** — смещение источника относительно центра экрана;
* дальше 1800 px звук не играет вовсе: это и тишина вместо каши,
  и сэкономленные голоса.

Точка прослушивания — камера игрока; в «горячем стуле» их две, и берётся
ближайшая. Свои события (попадание по себе, интерфейс, флаг) играют без
привязки к месту — их слышно всегда.

### Откуда берётся музыка

Источников два, и файлы всегда главнее:

```
music/combat/*   треки боя
music/menu/*     треки меню, гаража и итогов
```

Есть хотя бы один файл (.mp3, .ogg, .wav) — играют они, вперемешку
через `AudioStreamPlaylist` с секундной склейкой. Синтез для этой темы
даже не запускается: и полсекунды процессора на старте экономятся,
и звук заведомо лучше.

Папка пуста — тема синтезируется, как раньше. Это не запасной вариант
на всякий случай, а гарантия: игра звучит и без единого ассета.

Сведённую живую запись синтезатором на GDScript не догнать — там
настоящие инструменты, комната и мастеринг. Процедурный трек хорош
ровно до того момента, как появляется файл.

Чтобы добавить разнообразия, достаточно положить в папку ещё файлов:
список собирается при запуске и играет вперемешку.

Сейчас в бою играет `battle_v1.mp3` (3:16), в меню — процедурная
оркестровая тема с колоколом.

### Шины

Синтезированная тема идёт через шину `MusicHall` с реверберацией и лёгким
хорусом: сухой осциллятор звучит «в вакууме», и именно это ухо читает как
компьютерный звук. Файловая тема идёт напрямую — у записи своя комната уже
в миксе, и вторая поверх неё звучит как в бочке.

### Синтезированные темы

Тем две, и они намеренно противоположны.

**Меню — ре минор, 72 удара в минуту, 12 тактов, петля 40 секунд.**
Струнная секция, органная педаль в басу, литавры, медь, хор и колокол.
Тема сделана с аркой: первые три такта только струнные и педаль,
с четвёртого вступают литавры, с пятого медь, с седьмого — хор.
Прогрессия `Dm — Bb — F — C`, трижды.

Хор поёт «а», и это не просто синусоида: гласная — два бугра в спектре
(форманты), поэтому гармоники взвешены по близости к 750 и 1150 Гц. Без
этого получается орган, а не голоса.

### Колокол раз в 10 секунд

Яркий акцент темы — тяжёлый колокол, бьющий ровно каждые 10 секунд.
Раньше в этой роли была тарелка на 5-м такте (интервал 12.6 с); её
в теме больше нет.

**Колокол негармоничен** — этим он и отличается от гонга или литавры:
частичные тоны стоят не кратно основному. Набор классический: хум
(половина примы), прима, **малая терция**, квинта и номинал в октаву.
Минорная терция здесь ключевая — она и даёт тот траурный призвук, ради
которого колокол вообще ставят. Гаснут частичные с разной скоростью:
верхние уходят за секунду, хум гудит все пять. Поэтому удары раз в
10 секунд перекрываются хвостами и звучат как перезвон, а не как
отдельные ноты.

**Верхний ряд частичных — не украшение, а условие слышимости.** У колокола
с примой 73 Гц всё тело лежит ниже 150 Гц, а ноутбучный динамик там уже
почти ничего не отдаёт: первый вариант замерялся в полосе выше 2 кГц
как 0.011 против 0.07 у хора, то есть на встроенных динамиках это был
глухой удар, а не колокол. Добавлены частичные 4×, 5.33×, 6×, 8×, 10.7×
и 13.3× — они гаснут за секунду, как у настоящей бронзы, поэтому и
считаются короткими буферами: длинные стоили бы вчетверо дороже, ничего
не добавив. После правки удар даёт в полосе 250–1500 Гц (той, что играет
на любом динамике) 0.086 против 0.038 у окружающей музыки — колокол
слышен, а не угадывается.

### Сведение оркестра

Второй замер вскрыл проблему, которую на слух легко списать на «так
задумано»: во второй половине темы играет всё сразу, сумма слоёв
выходила далеко за единицу, и общий ограничитель (`tanh`) начинал не
подмягчать, а порождать гармоники. На чистых синусах хора это слышно
как грязь — в полосе выше 2 кГц было 0.074 при 0.011 в спокойных
тактах.

Лечится не лимитером, а уровнем: буфер темы приводится к пику 0.72
и проходит ограничитель с мягким перегрузом 1.7. Подбиралось замером:

| вариант | грязь (>2 кГц) | RMS темы | разрыв с боевой |
|---|---|---|---|
| как было | 0.074 | −12.4 дБ | 0 дБ |
| чистый запас (0.82, без перегруза) | 0.024 | −18.5 дБ | 6.1 дБ |
| **принято: 0.72 + перегруз 1.7** | **0.043** | **−15.2 дБ** | **2.8 дБ** |

Чистый запас убирал грязь лучше всех, но ронял тему на 6 дБ ниже боевой,
и вход в бой звучал скачком громкости. Принятая пара придавливает пики
на 3 дБ, тело почти не трогает и оставляет разрыв в те 3 дБ, которые
меню и положено быть тише боя.

Боевую тему это не касается: там перегруз — часть звучания, и она
собирается как раньше.

**Синхронизация решена темпом, а не таймером.** Требование — удар ровно
раз в 10 секунд; любой таймер, считающий по кадрам, рано или поздно
уплывёт от музыки. Поэтому интервал подогнан под музыкальную сетку:

```
72 уд/мин   ->  такт 3.3333 с  ->  10 с = ровно 3 такта
12 тактов   ->  петля 40.000 с ->  ровно 4 удара за петлю
```

Петля кратна периоду колокола, поэтому и на стыке петли интервал
остаётся те же 10 секунд. При прежних 8 тактах по 76 уд/мин петля длилась
25.26 с, и удары шли бы 10, 10, 5.26, 10, 10 — со слышимым сбоем на
каждом обороте. Замер готового буфера: длина 40.000 с, всплески на
10.0, 20.0 и 30.0 с (удар на 0.0 детектор не видит — перед ним нет
тишины).

Так рассинхрон невозможен по построению: он не «исправлен», а не может
возникнуть — колокол лежит в том же буфере, что и оркестр, и движок
проигрывает их одним потоком.

### Почему не отдельный источник по таймеру

Наложение колокола отдельным AudioStreamPlayer'ом по таймеру —
рабочий вариант, и для проекта на готовых аудиофайлах он был бы
основным. Здесь он проигрывает по трём причинам, но если музыка когда-то
станет файлом, делать надо так:

```gdscript
# Расписание ведётся по часам САМОЙ музыки, а не по delta кадра.
# Накопление delta уплывает: 60 кадров по 16.67 мс дают 1000.2 мс,
# и за десять минут набегает заметный сдвиг.
var _last_toll := -1

func _process(_delta: float) -> void:
    if not music.playing:
        return
    # Позиция + компенсация буфера звука: без неё удар опаздывает
    # на длину аудиобуфера, а она у разных драйверов разная.
    var pos := music.get_playback_position()         + AudioServer.get_time_since_last_mix()         - AudioServer.get_output_latency()
    var toll := int(floor(pos / BELL_PERIOD))
    if toll != _last_toll:
        _last_toll = toll
        bell_player.play()
```

Ключ в том, что номер удара **выводится из позиции трека**, а не
накапливается. Пропущенный кадр, просадка, перемотка, зацикливание —
номер всё равно посчитается верно, и удар не сдвинется.

Три причины, по которым здесь выбран запечённый вариант:

1. **Точность.** В буфере удар стоит на конкретном сэмпле — это ±0
   миллисекунд. Любой источник, запускаемый из `_process`, привязан
   к кадру: при 60 кадрах это ±16 мс, при просадке до 30 — ±33 мс.
   На фоне медленной оркестровой темы это слышно как неряшливость.
2. **Сведение.** Колокол в общем буфере проходит через то же мягкое
   ограничение (`tanh`), что и оркестр, — они звучат как один
   записанный материал. Отдельный источник суммируется уже после
   лимитера и на громких местах выпирает.
3. **Стоимость.** Отдельный плеер — это ещё один голос и ещё одна шина
   в звуковом движке на всё время работы игры. Запечённый колокол не
   стоит ничего сверх самой петли.

Отдельный источник выигрывает там, где интервал должен меняться на ходу
(например, ускоряться к концу отсчёта) или зависеть от событий игры.
Здесь он постоянный, поэтому выигрыша нет.

### Если переносить на другой движок

Постановка задачи упоминала Unity и Unreal — на случай переноса важно
то же самое правило: расписание ведётся по часам звукового движка,
а не по кадрам.

* **Unity.** Корутина `yield return new WaitForSeconds(10f)` квантуется
  кадром и уплывает. Правильный путь — `AudioSettings.dspTime`
  и `AudioSource.PlayScheduled(nextToll)`, где `nextToll += 10.0`
  **прибавляется** к расписанию, а не сбрасывается от «сейчас».
* **Unreal.** `SetTimer` с `bLooping` тоже привязан к тику. Для музыки
  используется Quartz: `UQuartzClockHandle` с квантованием по границе
  такта — тогда удар встаёт на музыкальную сетку, а не на кадр.
* **FMOD / Wwise.** Штатный приём — маркер на таймлайне или
  Sustain Point, и колокол как отдельный трек в том же событии; в Wwise
  это Music Segment с Custom Cue. Но для этого проекта middleware не
  подходит вовсе: в нём нет ни одного аудиофайла, весь звук
  синтезируется на запуске, а FMOD и Wwise работают с готовыми
  ассетами. Переход на них означал бы отказ от процедурного звука —
  и именно поэтому расписание здесь решено темпом.

**Бой — ми минор, 160 ударов в минуту, 8 тактов.** Костяк — гитарный
галоп шестнадцатыми: заглушенный ладонью чух с перегрузом ×4.5 и
призвуком медиатора. Поверх — квинт-аккорды без терции (она бы смягчила
звучание), бас, тяжёлая бочка в два слоя, малый и хэты. Во второй
половине петли бочка удваивается, а в конце каждой четвёрки тактов идёт
сбивка по томам: трек прибавляет, а не повторяет сам себя.

### Как это собирается

Собирать петлю плеерами из `_process` нельзя: кадр длится 16 мс, и
барабаны бы «плыли». Поэтому всё синтезируется в буфер, и движок получает
готовый зацикленный WAV — каждый удар стоит на своём сэмпле.

Главная хитрость — **кэш нот**. Синтез стоит около микросекунды на сэмпл,
подмешивание готового буфера — в тридцать раз дешевле. Поэтому каждая
нота считается один раз, а в петлю попадает столько раз, сколько нужно.
Аккорды темы меню подобраны так, чтобы делить между собой ноты: восемь
уникальных высот вместо тринадцати.

Сборка идёт двумя фоновыми задачами (`WorkerThreadPool`), параллельно
с эффектами. Меню — 4.7 с, бой — 0.7 с; до готовности играет тишина,
а тема поднимается кроссфейдом за 0.7 с. Оркестровая тема дорогая
из-за длинных нот с медленной атакой — это цена, которую платит только
запуск, и запуск она не блокирует.

### Связка с состояниями игры

| состояние | музыка |
|---|---|
| меню, гараж, итоги партии | тема меню |
| бой | боевая тема |
| **выбор перка** | **пауза** — трек останавливается и продолжается с того же места |
| меню паузы | приглушение на 14 дБ |

На выборе перка именно пауза, а не приглушение: это пауза боя, и тишина
отделяет её от стрельбы лучше, чем тот же трек потише. В меню паузы
наоборот — там игрок может задержаться надолго, и трек лучше оставить
фоном.

Переходы между темами идут кроссфейдом через два плеера: обрыв темы на
входе в бой слышен как сбой.

Проверяется отдельным тестом:

```
godot --headless --path . tests/music_state.tscn
```

Он прогоняет меню → бой → выбор перка → меню паузы → меню и проверяет,
что играет нужная тема, что на выборе перка стоит пауза и что после него
трек продолжился, а не начался заново.

### Сборка в фоне

Синтез эффектов занимает ~1.1 с и уходит в `WorkerThreadPool` вместе
с обеими темами: полсекунды тишины в меню никто не заметит, а полсекунды
чёрного экрана на запуске — заметят все. Пока набор не готов,
`Sfx.play` просто молча выходит.

Частота дискретизации — 32 кГц: половина времени сборки уходит на голый
перебор сэмплов в GDScript, а материал здесь — удары и шум, у которых
выше 16 кГц слушать нечего.

Проверяется всё выгрузкой в WAV:

```
godot --headless --path . tests/audio_dump.tscn
```

Сцена печатает время сборки и пик каждого звука и кладёт файлы в
`user://audio` — их можно послушать обычным плеером.

## Как устроен порт

* **Логика — обычные `RefCounted`-классы**, не узлы сцены. `World.step()`
  вызывается фиксированным шагом 60 Гц из `game.gd::_process`, ровно как
  в веб-версии. Это сохраняет весь баланс: «60 тиков = 1 секунда».
* **Отрисовка — immediate mode.** `WorldView._draw()` — построчный порт
  `render.js`: те же тайлы (5 вариантов крыш, песчаный берег, анимированная
  вода), те же танки с гусеницами, косметикой и индикаторами.
* **Разделённый экран** — по `SubViewportContainer` + `SubViewport` на игрока,
  внутри каждого свой `WorldView` со своей камерой и своим HUD-блоком.
* **Звук** генерируется процедурно при старте (`AudioStreamWAV` из
  синтезированных тонов и шума) — как Web Audio в оригинале, без ассетов.
* **Эмодзи** в интерфейсе работают за счёт запасного шрифта: к системному
  шрифту цепляется `Segoe UI Emoji` / `Noto Color Emoji` (`fonts.gd`).

## Отличия от веб-версии

1. **Нет онлайн-режима.** Убраны `net.js` и `server/`, из меню исчезла кнопка
   «Играть онлайн» — вместо неё «Выход».
2. **«Оборона»: первая волна.** В JS боты первой волны спавнились сразу
   в `#spawnCombatants`, а затем `#setupDefense` сбрасывал счётчик волн в 0 —
   из-за чего волна №1 фактически выходила дважды. Здесь волна №1 выходит
   один раз, через `start_delay` (4 сек) после начала партии.
3. **Рывок второго игрока** — Numpad `+` вместо правого Shift: Godot не
   различает левый и правый Shift на уровне физических клавиш.
4. **Фон меню перерисован под Godot.** Композиция та же по духу (гроза, танк
   на возвышенности, горящие остовы), но собрана заново: в `_draw()` нет
   аналогов `createLinearGradient` и `roundRect`, поэтому небо, засветки
   и виньетка сделаны на `GradientTexture2D`. Заодно добавлен разбитый город
   на горизонте и рельеф гребня.
5. **Сохранение** — `user://profile.json` вместо `localStorage`.

## Сборка для другого компьютера

Настройки экспорта лежат в [export_presets.cfg](export_presets.cfg): один
пресет «Windows Desktop», x86_64, с упакованными внутрь ресурсами
(`binary_format/embed_pck=true`). На выходе — **один самодостаточный
exe**, которому не нужен ни установщик, ни установленный Godot.

```
godot --headless --path . --export-release "Windows Desktop"
```

Готовый файл появится в `build/Tanchiki.exe` (~110 МБ, в zip ~38 МБ).
Папка `build/` в репозиторий не попадает.

Тесты (`tests/*`) из сборки исключены пресетом: игроку они не нужны.

Проверить собранный exe можно, не открывая окно:

```
build/Tanchiki.exe --headless --quit-after 240
```

Команда прогоняет 240 кадров и выходит с кодом 0, если ни один скрипт
не упал.

Требования на чужой машине — Windows 10/11 x64 и OpenGL 3.3: проект
собран на GL Compatibility, поэтому идёт на встроенной графике.
Сохранения и настройки живут в
`%APPDATA%\Godot\app_userdata\Тянчики — Battle Tanks`.

## Тесты

Дымовой прогон всех четырёх режимов без участия человека — 60 секунд игрового
времени на режим, с проверкой того, что танки заспавнились, не уехали за карту
и что боты действительно двигаются:

```bash
godot --headless --path godot res://tests/smoke.tscn
```

Снимки экранов (меню, гараж, галерея, бой, разделённый экран) для визуальной
сверки — складываются в `user://shots`:

```bash
godot --path godot --resolution 1280x720 res://tests/shot.tscn
```

Проверка звука — выгрузка всех буферов в WAV с печатью времени сборки
и пика каждого, и проверка связки музыки с состояниями игры:

```bash
godot --headless --path godot res://tests/audio_dump.tscn
```

```bash
godot --headless --path godot res://tests/music_state.tscn
```

Уровни 1–5 детерминированы по seed, поэтому карта, погода и стартовая
расстановка воспроизводятся один в один при каждом запуске.
